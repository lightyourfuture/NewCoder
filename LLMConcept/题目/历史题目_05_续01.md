- C. 采用稀疏注意力机制
- D. 提高优化器的学习率

C

在Transformer中,注意力计算的标准复杂度是O(n^2),其中n是序列长度.选项C(采用稀疏注意力机制)通过限制注意力范围(如只关注局部或随机位置),能将复杂度降低到O(n)或O(n log n),从而直接降低注意力计算的复杂度.选项A(使用更大的批次尺寸)可能提高训练效率但不改变序列级别的复杂度;选项B(增加FFN层的维度)影响Feed-Forward Network的计算,与注意力计算无关;选项D(提高优化器的学习率)只影响训练收敛,不改变算法复杂度.

首遍助手判断:C; 正确答案:C

Sparse Attention(稀疏注意力):只计算选定位置之间的注意力关系.FFN=Feed-Forward Network,前馈网络.Batch size(批量大小):一次处理的一批样本规模,与单序列注意力关系数量不是同一个量.

固定窗口 w 时,核心计算可由 O(n²d) 降为约 O(nwd);是否线性取决于稀疏模式和窗口是否随长度增长.

通俗大白话解释:
稀疏注意力不是让每个 token 都看所有 token,而是只看局部窗口,特定位置或重要 token,从而减少注意力计算量.

- B 会增加计算.
- D 是训练超参数,不解决注意力复杂度.

- Sparse Attention = 减少 token 间全连接注意力,降低长文本计算成本.

## 2026-07-06 注意力机制主要解决的序列建模问题

- B. 捕捉长距离上下文依赖关系

- C. 模型的参数设置
- D. 训练数据的数量

结论:
正确选项:B

大白话解析:
LIME(Local Interpretable Model-agnostic Explanations)是一个"归因侦探",它不关心模型内部怎么构造的,而是围绕某个具体预测结果,告诉你每个输入特征分别贡献了多少.比如判断一封邮件是垃圾邮件,"中奖"这个词贡献 +0.3,"正规平台"贡献 -0.1.

易错点:

- A 错,LIME 和训练时间无关.
- C 错,模型参数是模型内部信息,LIME 不需要输出参数.
- D 错,训练数据量是可解释性技术不关心的维度.

知识点总结:

- LIME = 局部可解释性工具,核心输出是各特征对单个预测的贡献大小.

## 2026-07-06 KV Cache 优化原理

来源:用户提供题目

题目:

> 关于大模型推理阶段的KV缓存优化,以下说法正确的是?

选项:

- A. 通过缓存激活函数输出值减少计算量
- B. 复用先前时间步的Key/Value矩阵避免重复计算
- C. 将浮点计算转换为整数计算加速推理
- D. 删除模型中间层的残差连接降低复杂度

结论:
正确选项:B

大白话解析:
大模型自回归生成时逐 token 输出,每个新 token 都要跟历史 token 做注意力计算.KV Cache 把之前 token 算过的 Key 和 Value 存起来,生成新 token 时直接复用,只算当前新 token 的 K/V.这样避免了每次生成都重算全部历史,大幅加速推理.

易错点:

- A 错,缓存的是 K/V 矩阵,不是激活函数输出.
- C 错,浮点转整数是量化技术,不是 KV Cache.
- D 错,残差连接不能随意删除,否则模型训练和推理都会出问题.

知识点总结:

- KV Cache = 存历史 K/V,只算当前 token,避免重复计算,加速自回归解码.

## 2026-07-06 数据清洗中评估数据完整性

来源:用户提供题目

题目:

> 数据清洗中,如何评估数据的完整性?

选项:

- A. 依赖于数据的数量
- B. 检查数据中缺失值的比例
- C. 只关注数据的准确性
- D. 不需要评估

结论:
正确选项:B

大白话解析:
数据完整性衡量数据"全不全".最直接的方法就是统计缺失值比例----缺失率越高,完整性越差.完整性和准确性是两个不同维度:数据可能完整但错误,也可能准确但缺字段.

- C 错,准确性是"对不对",完整性是"全不全",两个维度.
- D 错,完整性必须评估,否则无法判断数据质量.

知识点总结:

- 数据完整性 = 检查缺失值比例,缺的越少越完整.

## 2026-07-06 MoE 模型的核心特点

来源:用户提供题目

题目:

> 混合专家模型(Mixture of Experts, MoE)是当前构建超大规模语言模型的一种重要架构.关于 MoE 模型,以下哪个陈述是正确的?

选项:

- A. 在推理过程中,输入序列的每个token都会被路由到所有专家进行计算,以获得最佳性能.
- B. MoE 模型的总参数量巨大,因此其训练和推理所需的计算量必然高于同等参数量的稠密模型.
- C. 它的核心优势在于,尽管总参数量可以非常大,但在处理每个token时仅激活少数专家,从而使得单次前向传播的计算成本远低于同等总参数量的稠密模型.
- D. MoE 模型中的路由网络仅在预训练阶段进行学习,在微调阶段需要被冻结.

结论:
正确选项:C

大白话解析:
MoE 像一家有很多专家的公司:总参数量很大,但每个 token 经过路由网络后只激活其中少数几个专家.因此 MoE 既有大模型的容量,单次计算量又比同等总参数的稠密模型小得多.

- B 错,计算量看的是激活参数量而非总参数量,MoE 反而更省.
- D 错,路由网络在微调时也可以继续训练,不一定冻结.

知识点总结:

- MoE = 总参数大但每次只激活部分专家,容量高,单次计算省.

## 2026-07-06 多头注意力中每头维度计算

来源:用户提供题目

题目:

> 在Transformer的多头注意力机制中,假设模型维度为d_model=1024,使用16个注意力头,每个头的维度d_k为多少?

选项:

- A. 32
- B. 64
- C. 128
- D. 256

结论:
正确选项:B(64)

大白话解析:
多头注意力将 d_model 均匀拆分为 h 个头.计算公式:d_k = d_model / h = 1024 / 16 = 64.每个头在 64 维子空间独立计算注意力,最后拼接回 1024 维输出.

易错点:

- 容易算错除法:1024 ÷ 16 = 64,其他选项对应不同头数(32头/8头/4头).

知识点总结:

- d_k = d_model / num_heads,总维度除以头数得到每头维度.
