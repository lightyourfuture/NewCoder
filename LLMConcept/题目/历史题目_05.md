## 2026-06-15 题30 Scaling Laws 的正确描述

来源:用户提供 30 题随机组卷

题目:

> 关于Scaling Laws的发现,以下哪些描述是正确的?

选项:

- A. 模型性能(loss)与计算量,数据量,参数量之间存在幂律关系
- B. Chinchilla Scaling Law建议参数量和数据量应按大致1:20的比例增长
- C. Scaling Laws表明只要增大模型就能无限提升性能
- D. Scaling Laws可以帮助预测给定计算预算下的最优模型配置

结论:
正确选项:A,B,D

大白话解析:
Scaling Laws 发现模型 loss 和参数量,数据量,计算量之间常呈现可预测的幂律关系.Chinchilla 进一步强调参数量和训练 token 要按合理比例匹配,常见说法是每个参数约配 20 个训练 token.它还能帮助估算给定预算下更合适的模型规模和数据规模.

易错点:

- C 错.Scaling Laws 不表示无限提升,现实中受数据质量,计算预算,架构,优化和收益递减影响.

知识点总结:

- Scaling Laws = 用规律预测参数,数据,计算预算与性能之间的关系.

## 2026-06-16 题12 Tokenization 的工程挑战

来源:用户提供 30 题随机组卷

题目:

> tokenization作为大型模型输入处理的关键步骤,在实际应用中可能遇到的工程挑战是什么?

选项:

- A. 增加模型参数数量
- B. 处理罕见词或OOV(out-of-vocabulary)问题
- C. 提高模型生成速度
- D. 简化模型架构设计

本次复习记录：
- 批次：2026-10-17 Gemini第1轮 题1（接回标识，沿用原粘贴日期，非平台组号）。
- 重复题：完整题干及全部选项与本条既有题目一致，合并于此，未重复建题。
- 资料状态：题干、选项、官方答案及官方解析已对照2026-10-18补交的第一轮完整附件核验。

官方答案：
B

官方解析：
题目要求识别tokenization在大型模型输入处理中可能遇到的工程挑战。tokenization是将文本分割成tokens的过程，常见工程挑战包括处理罕见词或out-of-vocabulary（OOV）问题，例如当词汇表未覆盖某些词时，需要采用subword tokenization等策略来处理。选项B直接对应此挑战。其他选项无效：A（增加模型参数数量）是模型设计问题，无关tokenization；C（提高模型生成速度）更关联模型推理效率，而非tokenization的具体挑战；D（简化模型架构设计）是架构优化问题，与tokenization无关。题目无文字错误、逻辑矛盾、专业名称错误或规则破坏错误。

核对补充：
Gemini原记录首遍判断：B（原回复未逐题核实）。
用户本次作答：未提供，不据助手答案推算用户成绩。
本次助手复核判断：B。
选 B。OOV 是词表覆盖问题，现代分词器常通过子词或字节回退缓解。原补充把“现代大模型普遍采用字节级 BPE”“消灭未知词”说得过于统一；能否覆盖任意文本取决于具体分词规则与回退机制，不能概括为所有分词器均如此。

先弄懂题中概念：
- Tokenization（分词、词元化）：把文本切成可映射为整数编号的单位。
- Token（词元）：模型处理的基本离散单位，可以是字节、字符、子词或词，不是固定等于一个汉字。
- OOV（Out-of-Vocabulary，词表外词）：完整词未出现在既定词表中；不等于其字符无法被子词或字节表达。
- BPE（Byte-Pair Encoding，字节对编码）：反复合并常见相邻符号形成子词的算法；是否以字节为基础取决于实现。
- Embedding（嵌入层）：把词元编号转换成向量。词表越大，其参数存储通常也越多。

补充与扩展：
词级分词遇到未收录词时可能输出未知词标记；子词分词把它拆成已知片段，字节级方法还可用字节表示。覆盖率提高不代表所有工程问题都消失：罕见词若被拆得很碎，仍会占用更多上下文与计算。分词通常可逆，不应把切分直接说成丢失原始字符或语义必然损坏。

通俗大白话解释：
分词器像给文本编号码的字典。新词不在整词字典里，可以拆成字典认识的小片段；本题问的就是如何处理这些罕见词。A、D谈模型设计，C谈生成速度，都不如 B 直接。

易错点：
- 容易误以为分词器只负责按空格或标点切词,忽略了词表覆盖率与未登录词(OOV)回退机制的重要性.
- 容易混淆"分词粒度影响序列长度进而间接影响推理耗时"与"分词本身的工程挑战",误选 C.

知识点总结：
- Tokenization 的核心工程挑战是平衡词表大小与妥善处理罕见词/未登录词(OOV).
- 主流解决方案是采用子词分词(Subword Tokenization,如 Byte-level BPE).

### 历史解析（保留原记录）

结论:
正确选项:B

大白话解析:
Tokenizer 要把文本切成 token.遇到罕见词,专业术语,多语言,数字,代码时,可能切得很碎或表达不好,影响序列长度和模型理解.

易错点:

- Tokenization 不会增加模型参数数量.
- 它不直接提高生成速度.
- 它也不简化模型架构.

知识点总结:

- Tokenization 的难点包括 OOV,罕见词,多语言,数字和专业术语处理.

## 2026-06-16 题13 涌现能力的定义

题目:

> 在大型语言模型(LLM)的研究中,"涌现能力"(Emergent Abilities)通常指的是何种现象?

选项:

- A. 模型在训练初期就表现出的特定任务能力.
- B. 随着模型参数规模的增加,在小模型上不存在或表现不佳,但在大模型上突然显著出现的能力.
- C. 通过少量样本微调(Fine-tuning)后,模型在新领域获得的特定知识.
- D. 模型在推理时随机生成,无法复现的创造性输出.

官方答案:
B

官方解析:
在大型语言模型(LLM)研究中,'涌现能力'(Emergent Abilities)是一个标准术语,指随着模型参数规模的增加,某些任务能力在小模型上不存在或表现不佳,但在大模型上突然显著出现的现象,这一概念由相关研究(如Wei et al., 2022)定义,与选项B相符.选项A错误,因为涌现能力并非训练初期就表现出的能力;选项C描述的是few-shot学习或微调过程,与涌现能力无关;选项D强调随机性和不可复现性,而涌现能力是可靠,可预测的性能提升,与此不符.

核对补充:
首遍助手判断:B; 正确答案:B
答案与首遍一致.排除随机不可复现输出是合理的,但"涌现可靠,可预测"不能作为无条件结论;何种能力在哪一规模显现及是否呈突变,与任务,数据和评测指标有关.

先弄懂题中概念:
LLM(Large Language Model,大语言模型):用大规模数据训练的语言模型.Emergent Abilities(涌现能力):讨论随规模变化而显著显现的能力现象.Fine-tuning(微调):在已训练模型上继续适配任务.

补充与扩展:
判断涌现需明确模型家族,任务,规模区间和评测指标;参数规模不是脱离数据和训练条件的单一开关.

通俗大白话解释:
涌现能力强调能力不是线性慢慢变强,而是在模型规模达到某个阈值后突然明显出现.

易错点:

- A 是训练早期能力,不是涌现.
- C 是微调效果.
- D 是随机生成,不是涌现定义.

知识点总结:

- Emergent Ability = 小模型弱,大模型过阈值后能力显著出现.

## 2026-06-16 题14 Scaling Laws 的核心思想

来源:用户提供题目及官方答案,官方解析.

题型:单选题

题号:2026-10-16 第2组 7

平台知识点:大模型概念

本次复习:2026-10-16 第2组 7

题目:

> 关于大模型领域的"缩放法则"(Scaling Laws),以下哪项描述最准确地揭示了其核心思想?

选项:

- A. 模型的性能仅与模型参数量的增加呈对数关系
- B. 只要不断增加训练数据量,模型的性能就能无限提升
- C. 模型的性能损失是模型大小,数据集大小和用于训练的计算量这三个因素的可预测的幂律函数
- D. 缩放法则证明了Transformer是唯一能够实现性能可预测性扩展的架构

官方答案:
C

官方解析:
缩放法则的核心思想是模型的性能损失(如测试损失)与模型大小(参数量),数据集大小和用于训练的计算量这三个因素之间呈可预测的幂律函数关系,这基于Kaplan等人在2020年的研究(Scaling Laws for Neural Language Models).选项A错误,因为性能提升不限于参数量且关系是幂律而非仅对数;B错误,性能提升受饱和效应限制,不能无限提升;D错误,缩放法则可应用于其他架构(如RNNs或CNNs),并非证明Transformer是唯一的可扩展架构.

核对补充:
首遍助手判断:C; 官方答案:C
答案与首遍助手判断一致,官方解析的核心结论可作为本题解题依据.

补充与扩展:
幂律可示意为 L(x)≈L∞+a·x^(-α),但不能把三种资源看成完全独立或把某一个式子套用于所有模型和数据条件.


$$
L(x)\approx L_\infty+a x^{-\alpha}
$$


通俗大白话解释:
Scaling Laws 研究的是模型 loss 和参数量,数据量,计算量之间的规律,通常可以用幂律关系预测趋势.

易错点:

- A 只看参数量,太窄.
- B "无限提升"错误.
- D 没有证明只有 Transformer 才能扩展.

知识点总结:

- Scaling Laws = 用参数,数据,计算量预测性能损失变化.

- B. 复用先前时间步的Key/Value矩阵避免重复计算
- C. 将浮点计算转换为整数计算加速推理
- D. 删除模型中间层的残差连接降低复杂度

结论:
正确选项:B

大白话解析:
大模型自回归生成时逐 token 输出,每个新 token 都要跟历史 token 做注意力计算.KV Cache 把之前 token 算过的 Key 和 Value 存起来,生成新 token 时直接复用,只算当前新 token 的 K/V.这样避免了每次生成都重算全部历史,大幅加速推理.

易错点:

- A 错,缓存的是 K/V 矩阵,不是激活函数输出.
- C 错,浮点转整数是量化技术,不是 KV Cache.
- D 错,残差连接不能随意删除,否则模型训练和推理都会出问题.

知识点总结:

- KV Cache = 存历史 K/V,只算当前 token,避免重复计算,加速自回归解码.

## 2026-07-06 数据清洗中评估数据完整性

题目:

> 数据清洗中,如何评估数据的完整性?

选项:

- A. 依赖于数据的数量
- B. 检查数据中缺失值的比例
- C. 只关注数据的准确性
- D. 不需要评估

结论:
正确选项:B

大白话解析:
数据完整性衡量数据"全不全".最直接的方法就是统计缺失值比例----缺失率越高,完整性越差.完整性和准确性是两个不同维度:数据可能完整但错误,也可能准确但缺字段.

易错点:

- A 错,数据量大不代表每行都完整.
- C 错,准确性是"对不对",完整性是"全不全",两个维度.
- D 错,完整性必须评估,否则无法判断数据质量.

知识点总结:

- 数据完整性 = 检查缺失值比例,缺的越少越完整.

## 2026-07-06 MoE 模型的核心特点

题目:

> 混合专家模型(Mixture of Experts, MoE)是当前构建超大规模语言模型的一种重要架构.关于 MoE 模型,以下哪个陈述是正确的?

选项:

- A. 在推理过程中,输入序列的每个token都会被路由到所有专家进行计算,以获得最佳性能.
- B. MoE 模型的总参数量巨大,因此其训练和推理所需的计算量必然高于同等参数量的稠密模型.
- C. 它的核心优势在于,尽管总参数量可以非常大,但在处理每个token时仅激活少数专家,从而使得单次前向传播的计算成本远低于同等总参数量的稠密模型.
- D. MoE 模型中的路由网络仅在预训练阶段进行学习,在微调阶段需要被冻结.

正确选项:C

- D 错,路由网络在微调时也可以继续训练,不一定冻结.

知识点总结:

- MoE = 总参数大但每次只激活部分专家,容量高,单次计算省.

## 2026-07-06 多头注意力中每头维度计算

来源:用户提供题目

题目:

> 在Transformer的多头注意力机制中,假设模型维度为d_model=1024,使用16个注意力头,每个头的维度d_k为多少?

选项:

- A. 32
- B. 64
- C. 128
- D. 256

结论:
正确选项:B(64)

大白话解析:
多头注意力将 d_model 均匀拆分为 h 个头.计算公式:d_k = d_model / h = 1024 / 16 = 64.每个头在 64 维子空间独立计算注意力,最后拼接回 1024 维输出.

易错点:

- 容易算错除法:1024 ÷ 16 = 64,其他选项对应不同头数(32头/8头/4头).

知识点总结:

- d_k = d_model / num_heads,总维度除以头数得到每头维度.
