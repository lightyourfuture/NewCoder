# 历史网页端交接规则（当前不启用）

以下为2026-10-29之前的历史流程，仅供追溯。现行规则以根目录工作流为准；用户明确重新启用网页模式时再检查其适用性。

### 历史网页模式（当前不启用）

- 网页端没有项目访问能力时,不要求它检索本地文件或上传全部历史笔记.在每批说明“历史查重待本地接回核验”,不能宣称没有重复,已经查重或已经保存文件.
- 第一遍仍完整展示原题并独立解析.第二遍生成可复制的 Markdown 源码,由用户追加到指定的现有专题 `NOTES.md`;不创建额外的原题副本,官方原文文件或批次汇总.源码以实际用户材料为准,不能因为没有官方解析也生成“已正式归档”笔记.
- 给每套不同试卷确定稳定的交接批次标识,如“日期＋网页端第1轮”,并写出首题和末题关键词以便核对.这只是交接标识,不是平台组号.同一试卷的第一遍,第二遍,重发或续传都沿用该标识,不因重发而算成新试卷;第二套不同试卷使用新标识.
- 开始前实际清点题号,题型,选项,官方答案和解析覆盖范围.题型标签紧挨下一题题号时,按所属题目归位;首题标签缺失而无法确定时说明待核实,不能拿上一题末尾的标签误判本题.用户作答与官方答案分别保留,多选题也不能把助手答对当成用户答对.
- **本网页模式允许跨消息分段,是默认同轮完整处理规则的明确例外.** 默认每条回复完整处理5题,第二遍每条只输出这5题的一个完整 Markdown 代码块,下一条从下一题继续.不要在同一个超长回复里放多个代码块就声称解决输出上限.用户可指定其他分段大小;不得以节省长度为由减少题干,选项,官方解析或必要解释.
- 每段代码块内标明批次,阶段,题号范围及实际题数,并在全部题目完整结束后添加完成标记,例如 `<!-- 本段完成：网页端第1轮；第二遍；1–5题；实际5题；下一段6–10题 -->`.未写完一题或未正常闭合代码块时,该段不得标完成.外层代码围栏需避免被题内代码提前关闭,必要时使用四个反引号作为外层围栏.
- 一段复制或下载完成不等于全卷已保存.用户确认本段保存后,仅继续下一段.全部预期题号均已完整输出后才可称“整批源码已输出”;没有读取本地文件,仍只能说明由用户手工保存,不能代替用户确认或称“本地已核验”.
- 输出中断时,以实际完整题目和完成标记为准.重发本段不会增加刷题次数.用户不确定上一段是否保存时,先核对批次与完整题号范围,避免反复从第1题重来或把两份残段同时追加.不得猜测网页的固定Token上限,缓存故障或“停止生成会抹除历史”等内部机制来解释原因;没有证据就说原因未确认.
- 源码只放实际要粘贴的笔记内容,不夹带答题卡,下载说明,网页引用图标或聊天回执.公式按正常 Markdown/LaTeX 源码保留,不要把反斜杠多转义一层.无需用户授权新增导出文件或额外报告来记录分段状态.

### 从网页端接回本地的检查顺序

1. 先以本地实际保存内容为证据,逐批数完整题干,选项和官方解析,检查最后一题是否截断.分别说明“原卷题量”“本地出现的题号”“官方内容齐全的题数”,不要用助手回执中的“已完成30题”替代检查.
2. 将用户原始附件或完整平台复制文本作为题面与官方解析的主要核对依据.网页助手生成的 Markdown 是待检查的转录结果.本地文件,原始材料,可见对话片段及助手自述是不同证据,报告判断时讲明依据.
3. 看不到完整对话只能说未完整读取或首遍判断未核实,不能推断用户没做题或没发官方解析.优先检查已有原文,再说明具体缺失题号和缺失字段.不能用助手猜写来补官方原文,也不能依据概念相似的旧题拼造缺失原题.
4. 查重时先用题干关键词定位少量候选,再对照全文及全部选项,避免为每题反复读取整个项目.只合并本次接回范围内已确认的完全重复题,原题已有完整内容时保留,另存本次官方解析及复习批次到同一条记录.相似题仅关联,不合并;不趁接回重排所有历史题目.
5. 修复助手解释时特别检查绝对化承诺和概念混淆,例如把PPO-Clip说成概率比的硬约束,把标准化说成变成正态分布,把FlashAttention说成降低稠密注意力的二次计算复杂度,或保证量化必定加速.保留官方原文,助手错误在助手栏目改正并说明,必要时附原论文或官方文档.
6. 第二遍题目逐项对照来源,记录实际用户错答.核对题号连续性,所有选项,官方解析末尾及公式,再检查重复合并后每个批次原题号仍能定位.只在对应现有笔记及用户要求优化的本文件中修复,不自动更新工作记忆或新建交接报告.
7. 未取得原文的部分保留明确待补状态,其余部分先完成.最终按“已核验”“仅沿用已存内容”“待补”分别报告,不把部分恢复写成两轮全部归档完成.

### 可直接发给网页端助手的启动提示
