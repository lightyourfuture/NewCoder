## 2026-11-01 第6组 题1 在以下Agent架构中，哪种最适合需要长时间运行（数小时/天）的复杂任务？

题型：单选题

题号：1

题目：

> 在以下Agent架构中，哪种最适合需要长时间运行（数小时/天）的复杂任务？

选项：

- A. 无状态的ReAct Agent
- B. 有检查点持久化和任务队列的异步Agent
- C. 流式输出Agent
- D. 规则驱动Agent

官方答案：
B

官方解析：
长时间运行任务需要：1) 状态持久化（中断后可恢复）；2) 异步执行（不阻塞主线程）；3) 任务队列（管理多任务）；4) 进度监控和通知。单纯的ReAct Agent没有持久化机制，连接断开后状态丢失。

用户作答：未逐题显示；批次成绩见卷首。

核对补充与术语解释：

首遍助手判断：B；与官方答案一致。

核对与必要纠错：B 正确，与[第1组题25](2026-11-01_第1组_续02.md#agent-20261101-01-25)考点相近，但更强调可靠执行架构，非完整重复。ReAct 是推理—行动范式，并不天然禁止持久化；官方“单纯ReAct没有持久化、连接断开就丢状态”只适用于未实现状态保存且状态随连接生命周期丢弃的具体实现。异步也不自动保证可靠，需持久队列、任务确认、重试去重及副作用恢复。

关键术语：Checkpoint（检查点）保存执行进度；Persistence（持久化）使进度在重启后可恢复；Task Queue（任务队列）安排工作分发；Asynchronous Execution（异步执行）让用户请求不必等待任务完成。Agent（智能体）根据目标决策和行动；ReAct（Reasoning and Acting，推理与行动相结合）不是状态存储后端。

逐项分析：A 明确无状态，不利于长任务恢复；B 同时覆盖调度和恢复；C 流式输出改善展示，不替代持久化；D 描述决策方式，规则驱动也可以做长任务，但仍需恢复设施。

通俗解释与记忆点：任务可以做一天，重启后要知道做到哪。记忆点：异步安排执行，持久状态支持接续，去重避免重复业务动作。

## 2026-11-01 第6组 题2 在Anthropic的Computer Use中，以下哪种操作不是Claude Computer Use的基本能力之一？

题号：2

题目：

- B. 鼠标点击和键盘输入
- C. 直接修改操作系统内核
- D. 应用程序控制

C

Claude Computer Use通过截图-行动循环控制计算机：获取屏幕截图分析当前状态，执行鼠标移动/点击、键盘输入等操作，控制浏览器和桌面应用程序。修改操作系统内核是系统级特权操作，不是此能力的范畴。

首遍助手判断：C；与官方答案一致。

核对与必要纠错：C 正确，题目问“不是”。官方文档介绍截图及鼠标、键盘控制，并由应用在受控环境执行。修改内核不是基本交互工具，但不能推断系统影响绝对不可能：若环境提供高权限终端，界面操作也可能间接执行系统级命令，须区分能力接口与授予权限。[Claude Computer Use 文档](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)

逐项分析：A 截图分析属于状态理解；B 属于基本交互；C 不是基本能力，本题应选；D 可通过界面操作浏览器或桌面应用实现。

通俗解释与记忆点：像人一样看屏幕、点鼠标、敲键盘，不是自带内核修改器。记忆点：看界面、操作界面；别漏读“不是”。

## 2026-11-01 第6组 题3 以下哪种方法最适合让Agent"学习用户偏好"（如某用户偏好简洁回复，另一用户偏好详细）？

题型：单选题

题号：3

题目：

> 以下哪种方法最适合让Agent"学习用户偏好"（如某用户偏好简洁回复，另一用户偏好详细）？

选项：

- A. 对所有用户使用相同的回复风格
- B. 将用户偏好显式存储在长期记忆（user_id → 偏好配置），每次会话时检索并注入system prompt（"该用户偏好简洁回复，使用要点格式"）
- C. 通过A/B测试随机切换回复风格
- D. 让用户每次都手动指定偏好

官方答案：
B

官方解析：
用户偏好学习的实现：①显式偏好：用户明确说"我喜欢简洁的回复"→存储到用户画像数据库；②隐式偏好：追踪用户的反馈行为（修改了哪些部分、重新生成了哪些回复）→推断偏好；③偏好存储：以JSON存储（{"response_length": "concise", "format": "bullet_points", "expertise_level": "advanced"}）；④注入：每次会话开始时检索该用户的偏好，注入system prompt个性化Agent行为。这是商业AI产品个性化体验的核心机制。

用户作答：未逐题显示；批次成绩见卷首。

核对补充与术语解释：

首遍助手判断：B；与官方答案一致。

核对与必要纠错：B 正确，与[第2组题10](2026-11-01_第2组.md#agent-20261101-02-10)同考点而非同题。偏好持久保存后须在需要时读取；显式偏好和推断偏好应区分，后者可能误判，应可纠正。一次修改不必成为永久偏好，当前明确要求应优先于旧配置；按用户隔离访问。

关键术语：Long-term Memory（长期记忆）保存跨会话有用信息；User Profile（用户画像）组织偏好等属性；`user_id` 是用户标识；system prompt（系统提示词）提供行为指令。LLM（Large Language Model，大语言模型）；JSON（JavaScript Object Notation，JavaScript 对象表示法）可保存结构化偏好。A/B 测试是分组对照实验，不等于为每人学习偏好。

逐项分析：A 无个性化；B 保存并使用用户偏好；C 随机分组比较策略不等于跨会话记忆；D 可用于提供偏好，但每次重述增加负担。

通俗解释与记忆点：记住这个用户喜欢怎样沟通，下次见面接着用。记忆点：长期保存、按需读取、允许修正、当前要求优先。

## 2026-11-01 第6组 题4 以下关于Agent "Token Budget"（Token预算）管理的描述，哪项正确？

题型：单选题

题号：4

题目：

> 以下关于Agent "Token Budget"（Token预算）管理的描述，哪项正确？

选项：

- A. Agent不需要考虑Token消耗
- B. 需要为不同组件（系统提示/工具描述/历史记录/工作内存）分配合理Token比例
- C. 历史记录应该完整保留，不能压缩
- D. 只需要关注输出Token数量

官方答案：
B

官方解析：
Agent的上下文窗口是有限资源，需要合理分配：系统提示（固定）+工具列表（固定）+对话历史（动态压缩）+工作记忆（当前任务状态）+当前轮输入/输出。历史记录需要摘要压缩以防止溢出。

用户作答：未逐题显示；批次成绩见卷首。

核对补充与术语解释：

首遍助手判断：B；与官方答案一致。

核对与必要纠错：B 正确。系统提示和工具列表也可以随任务或权限调整，不必如官方括注那样永久“固定”；分配比例应动态适配。外部可保存完整历史，输入上下文则按预算选择、摘要或检索，并预留输出及相应推理空间。与[PromptEngenering历史预算题](../../PromptEngenering/题目/历史题目_03.md#s-03-008)相近，题面不同，历史记录保留原处。

关键术语：Token（词元）是模型处理文本的基本单位，不严格等于一个字或词；Token Budget（词元预算）分配上下文和调用消耗；Context Window（上下文窗口）是单次处理的信息容量；Working Memory（工作记忆）保存当前任务状态。输入预算、输出预算和整项任务累计消耗需分别关注。

逐项分析：A 忽视上下文、成本与延迟；B 按重要性安排组件空间最合适；C 原文可外存而模型输入可压缩；D 输入和多轮工具结果同样消耗资源。

通俗解释与记忆点：行李箱有限，关键规则和当前目标先放进去。记忆点：预算看输入、输出与累计消耗，不背固定百分比。

## 2026-11-01 第6组 题5 ReAct框架中，Thought、Action、Observation三个步骤各自的作用是什么？

题型：单选题

题号：5

题目：

> ReAct框架中，Thought、Action、Observation三个步骤各自的作用是什么？

选项：

- A. Thought用于存储记忆，Action执行计算，Observation提供反馈
- B. Thought是推理步骤，Action是调用工具/执行操作，Observation是工具返回的结果，三者循环直到任务完成
- C. Thought是用户输入，Action是模型输出，Observation是评估结果
- D. 三个步骤必须严格按序执行，缺一不可

官方答案：
B

官方解析：
ReAct（Yao et al. 2022）将推理（Reasoning）和行动（Acting）交织：Thought让模型明确推理意图（"我需要先查询X"）；Action调用具体工具（搜索、计算器、API等）；Observation接收工具返回结果。这个循环使模型能动态调整行动策略，相比纯提示链（CoT）更灵活，相比直接行动更可控。

用户作答：未逐题显示；批次成绩见卷首。

核对补充与术语解释：

首遍助手判断：B；与官方答案一致。

核对与必要纠错：B 正确，保留首遍关于停止条件的限定：无需继续调用工具时可结束，失败或预算用尽也应有退出路径，不是无限循环到成功。官方对比 CoT/直接行动是在解释设计动机，不能据此保证任何任务都更优。与[历史ReAct题](历史题目_01.md#s-01-001)及[Prompt专题题](../../PromptEngenering/题目/历史题目_03.md#s-03-014)考点相近，题面不同。

关键术语：ReAct（Reasoning and Acting，推理与行动相结合）；Thought（推理/决策说明）选择下一步；Action（行动）调用工具或执行操作；Observation（观察）接收执行反馈；CoT（Chain of Thought，思维链）以中间推理步骤辅助解题；API（Application Programming Interface，应用程序编程接口）供程序调用外部能力。

逐项分析：A 把推理误作存储，行动也不限于计算；B 准确概括交互循环；C 混淆用户输入与执行步骤；D 把常见结构绝对化，忽视结束或无需工具的情况。

通俗解释与记忆点：想下一步，动手做，看结果，再决定是否继续。记忆点：Thought 决策，Action 行动，Observation 反馈。

## 2026-11-01 第6组 题6 以下哪种技术使Agent能够有效处理"数值计算"任务而不依赖LLM进行复杂数学计算？

题型：单选题

题号：6

题目：

> 以下哪种技术使Agent能够有效处理"数值计算"任务而不依赖LLM进行复杂数学计算？

选项：

- A. 让LLM直接计算
- B. 调用专用数学工具（Python解释器/计算器API），将计算任务委托给精确工具
- C. 训练更强的数学LLM
- D. 通过提示词引导LLM计算

官方答案：
B

官方解析：
LLM在数值计算上本质上是不可靠的（浮点运算、大数乘法等容易出错）。最佳实践：Agent识别到需要精确计算时，调用Python代码执行器、WolframAlpha API或自定义计算器工具，将精确计算外包给确定性工具，LLM只负责理解问题和解释结果。

用户作答：未逐题显示；批次成绩见卷首。

核对补充与术语解释：

首遍助手判断：B；与官方答案一致。

核对与必要纠错：B 正确。把运算交给工具可减少直接文本算术错误，但“确定性工具”不等于任意结果都精确：输入、公式、代码、单位和数值精度均可能出错。浮点可能舍入，大数需合适整数实现，精确小数或符号问题要用相应工具；模型还可负责列式与结果验证，不只解释。

关键术语：Numerical Computation（数值计算）用算法处理数值；Interpreter（解释器）执行程序；Determinism（确定性）指给定条件下行为可复现，不等于准确性；Floating Point（浮点数）用有限精度表示数值。WolframAlpha 是计算知识服务，API 是其程序调用接口。

逐项分析：A 仍让模型直接算；B 将运算委托计算工具最符合；C 可能提升能力但未外包运算；D 提示引导仍不提供执行计算的保证。

通俗解释与记忆点：模型列式，计算器算；式子错了，算得稳定也错。记忆点：外包运算，不外包输入、精度和结果核验。

## 2026-11-01 第6组 题7 以下哪种策略最适合在Agent系统中实现"知识边界"（Knowledge Boundary）管理？

题型：单选题

题号：7

题目：

> 以下哪种策略最适合在Agent系统中实现"知识边界"（Knowledge Boundary）管理？

选项：

- A. 让Agent回答所有问题，包括不确定的
- B. 明确定义Agent的知识范围，超出范围时给出明确的"不知道"并推荐替代方案
- C. 扩大Agent知识范围到无限大
- D. 对所有问题给出相同置信度

官方答案：
B

官方解析：
知识边界管理：1) 定义Agent明确"知道"的领域（通过知识库或训练数据）；2) 识别超出范围的查询（置信度低、话题域外）；3) 诚实地说明限制（"这超出了我的知识范围，建议咨询XXX"）；4) 提供替代资源或升级路径。这是高可信度Agent的核心特征。

用户作答：未逐题显示；批次成绩见卷首。

核对补充与术语解释：

首遍助手判断：B；与官方答案一致。

核对与必要纠错：B 正确。知识范围与适用边界不等于能从训练数据直接精确列出“所有知道的内容”，自报高置信度也不证明有依据。应结合可用证据、资料时效和工具能力识别缺口；未知部分可以检索、澄清或转交，不必把整个任务一律拒绝。

关键术语：Knowledge Boundary（知识边界）是知识、证据及适用范围的限制；Out-of-domain（域外）指超出既定业务领域；Confidence（置信度）是可信程度估计，未经校准不等于实际正确率；Escalation（升级处理）将问题转交更适合的资源或人员。

逐项分析：A 容易把未知编成确定答案；B 说明限制并提供替代路径；C 知识无限不现实；D 相同置信度不能反映证据差异。

通俗解释与记忆点：知道的说清楚，不知道的指出缺口并给下一步。记忆点：承认边界，补足信息，不凭语气判断可靠性。

## 2026-11-01 第6组 题8 以下哪种技术允许Agent学习用户的行为模式并个性化其服务？

题型：单选题

题号：8

题目：

> 以下哪种技术允许Agent学习用户的行为模式并个性化其服务？

选项：

- A. 硬编码用户偏好
- B. 用户偏好建模：从交互历史提取偏好向量，通过相似度检索匹配当前场景
- C. 让用户每次明确说明偏好

题号：9

选项：

- A. Agent反思只能用于错误纠正
- B. Agent在完成任务后对结果进行自我评估，识别改进点，可能触发重新执行
- C. 反思机制会显著增加Token消耗但不改善结果

## 2026-11-01 第6组 题10 以下关于OpenAI Assistants API与自定义Agent框架的比较，描述正确的是？

题型：单选题

题号：10

题目：

> 以下关于OpenAI Assistants API与自定义Agent框架的比较，描述正确的是？

选项：

- A. Assistants API在所有场景下都优于自定义框架
- B. Assistants API提供托管的内置功能（代码解释器、文件搜索、线程管理），适合快速开发；自定义框架灵活性更高，适合复杂自定义需求
- C. Assistants API不支持工具调用
- D. 自定义框架无法实现Assistants API的功能

官方答案：
B

官方解析：
Assistants API优势：内置Thread（对话历史管理）、Run（异步执行）、File Search（内置RAG）、Code Interpreter（沙箱代码执行），减少大量基础工程工作，适合快速原型。自定义框架（LangGraph/AutoGen）优势：完全控制执行逻辑、支持任意LLM（不限OpenAI）、更灵活的状态管理和错误处理，适合复杂生产需求。选择取决于定制化程度和开发资源。

用户作答：未逐题显示；批次成绩见卷首。

核对补充与术语解释：

首遍助手判断：B；与官方答案一致。

核对与必要纠错：B 按历史产品语境成立，与首遍一致。截至2026-11-01，官方迁移页说明 Assistants API 已于2026-08-26下线，不再可用，新集成使用 Responses API，不能把题目当当前选型建议。自定义框架对模型、控制流的支持也取决于实际集成，不应把“任意LLM”当无适配保证。[OpenAI 官方迁移文档](https://developers.openai.com/api/docs/assistants/migration)

关键术语：Thread 是旧 API 中管理会话历史的对象，不是操作系统线程；Run 表示一次运行；File Search（文件检索）和 Code Interpreter（代码解释器）是历史托管工具。RAG（Retrieval-Augmented Generation，检索增强生成）将检索资料用于回答；Managed Service（托管服务）由提供方承担部分基础工程，自定义编排提供更多控制。

逐项分析：A 无方案在全部场景占优；B 概括历史托管与自定义取舍；C 错误否认历史工具调用；D 类似能力可自行实现，但需承担工程成本。

通俗解释与记忆点：历史上是买现成功能还是自己搭框架，旧接口下线后另查现行方案。记忆点：历史题选B，当前状态按官方文档。
